# 設計レポート冗長性削減（プロンプト指示の追加）

## 作業日時
2026-04-12 16:24

## 概要

issue [acetokyo-com/nextream-api#178](https://github.com/acetokyo-com/nextream-api/issues/178) のレビュアーFB「外してないけどちょっと冗長な記述が多いかな」を受け、`buildDesignDecisionPrompt` の指示文・テンプレート例を5箇所修正して、生成レポートの冗長性を削減する。

直前の PR [Everforth/nestjs-commit-recap#5](https://github.com/Everforth/nestjs-commit-recap/pull/5) で「データ構造の変化」セクション・「把握できなかった意図」セクションの**期間グローバル**な抑制は入ったが、`reports/weekly-design-catchup-20260411.md` を見ると以下の冗長性が残存していたため追加対応する:

1. ドメイン単位の「データ構造の変化 / 変更なし」プレースホルダ（4/5 ドメインで該当）
2. 「〜を前提としている」の機械的な語尾反復
3. 同一PRリンクの大量重複（1ドメイン内で同じPRが5回など）
4. 「その他補足」が実装ディテール（メソッド追加・依存追加・env追加）のダンプ場化
5. 全体トーンガイドの不在

コードロジックは変更せず、プロンプトの指示文と例示の追加・差し替えのみで対応する（instruction-only / LLM任せのアプローチ）。

## 変更内容

### `src/design-decisions/prompts.ts`

5箇所の指示文・例示を追加・差し替え。

1. **冒頭に「文体ガイド」セクションを追加** （関数冒頭、役割宣言の直後）
   - 各bullet 40〜80字の長さ目安
   - 定型句の機械反復禁止（語尾のバリエーション・体言止め可）
   - セクション間の事実重複禁止
   - 実装ディテール省略
   - 既出固有名詞の再掲禁止

2. **per-domain「データ構造の変化」スキップ指示**（テンプレート例＋詳細記載方法ブロック）
   - テンプレート例の直前に「該当ドメインのEntity変更が存在する場合のみ出力。なければセクションヘッダごと省略。プレースホルダ記載は禁止」を追加
   - 「データ構造の変化セクションでの記載方法」ブロックの先頭にも同等の per-domain ルールを再掲

3. **「この設計が前提としていること」の例示を体言止めに差し替え**
   - 「〜を前提としている」の機械反復を禁止する明示的な指示を追加
   - 例文を体言止めの短文形に差し替え（few-shot で AI のスタイル伝播を狙う）

4. **PRリンクのグルーピングルールを追加**（ドメイン別サマリーの直前）
   - ドメイン内で参照PRが1〜2件: 見出し直下に `**関連PR:** [#番号](url)` 形式で1行集約
   - 3件以上のときのみ各bullet末尾に `*← [#番号](url)*` を付与
   - 同一PRリンクの5回以上の反復を禁止
   - テンプレート例側にも対応する注記を追加

5. **「その他補足」の除外条件を明示**
   - Step 2 の説明に「1ドメインあたり最大4項目」と除外条件の要約を追記
   - 「その他補足セクションの記載方法」ブロックに `### 除外条件（「その他補足」に記載してはいけないもの）` サブセクションを新設し、メソッド追加・依存パッケージ追加・env追加・ファイル名追加・既出固有名詞の再掲を禁止と明記

## 検証方針

### 自動: 次回 weekly cron 実行

`weekly-design-catchup.yml` GitHub Actions の次回実行（来週 2026-04-17 前後）で生成される issue を確認:
- 「データ構造の変化 / 変更なし」プレースホルダが消えていること
- 「前提としていること」の bullet 全部が「を前提としている」で終わっていないこと
- 同一PRリンクが1ドメイン内で3回以上反復していないこと（集約形式の採用）
- 「その他補足」に `multer`・新規メソッド名・env名などのノイズが消えていること
- レポート全体の文字数が `reports/weekly-design-catchup-20260411.md` より明確に短くなっていること（30%減程度を目安）

### 手動 (任意): ローカルでドライラン

`src/design-decisions/generate-cli.ts` 経由で同期間 (2026-04-03〜2026-04-10) のデータでローカル CLI を流して出力差分を比較。Anthropic API 1リクエスト分のコストが発生する。

## やらないこと

- ドメイン分類をコード側に寄せる構造変更（案B）— 来週の出力で instruction-only の効果を見て判断する
- データフロー・型定義の変更
- レポート生成パイプラインの他フェーズ（`data-collector.ts`, `report-generator.ts`）の修正
- 検証用のテストコード追加（週次出力での目視確認とする）
